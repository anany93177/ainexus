## 2. Context‑Aware Prompt Templates
Below are *complete reusable prompt templates* for each category. Every template contains:
- **Purpose** – what the template is meant to achieve.
- **Runtime Variables** – placeholders that will be filled at execution time.
- **Prompt Template** – the exact text sent to the LLM (variables in double braces `{{}}`).
- **Expected Output** – the shape or style of the answer the model should produce.
- **Validation Rules** – checks the response must satisfy before being accepted.
- **Failure Conditions** – situations that trigger fallback or retry.

### 3.1 Lesson Q&A
**Purpose**: Provide a concise, accurate answer to a learner’s question using the lesson content.
**Runtime Variables**:
- `{{user_query}}` – raw learner question.
- `{{lesson_content}}` – excerpt(s) from the lesson that match the query.
- `{{lesson_metadata}}` – lesson ID, title, difficulty.
- `{{conversation_history}}` – last few turns.
**Prompt Template**:
```
You are a knowledgeable tutor for the Nexus Learning platform.
Lesson: {{lesson_metadata.title}} (ID: {{lesson_metadata.id}})
Difficulty: {{lesson_metadata.difficulty}}

Context:
{{lesson_content}}

Conversation History:
{{conversation_history}}

User Question:
{{user_query}}

Answer the question directly, citing the relevant part of the context using the format "[Citation]". Keep the answer under 150 words.
```
**Expected Output**: Plain‑text answer (≤ 150 words) with at most one citation tag.
**Validation Rules**:
1. Length ≤ 150 words.
2. Contains at least one citation if a specific fact is referenced.
3. No profanity, hate‑speech, or disallowed content.
**Failure Conditions**:
- Exceeds word limit → truncate and re‑prompt.
- No citation when context includes a specific fact → request citation.
- Safety violation → invoke Toxic Prompt fallback.

### 2.2 Lesson Summary
**Purpose**: Generate a succinct summary of a lesson for quick revision.
**Runtime Variables**:
- `{{lesson_content}}` – full lesson body.
- `{{lesson_metadata}}` – title, ID, tags.
**Prompt Template**:
```
Summarize the following lesson in 3–4 bullet points. Use the lesson title "{{lesson_metadata.title}}" and include the most critical concepts. Keep each bullet under 20 words.

Lesson Content:
{{lesson_content}}
```
**Expected Output**: Markdown bullet list (3–4 items).
**Validation Rules**:
1. Exactly 3–4 bullet points.
2. Each bullet ≤ 20 words.
3. No duplicate points.
**Failure Conditions**:
- Wrong number of bullets → ask LLM to adjust.
- Exceeds word count → truncate.
- Repetition → request revision.

### 2.3 Quiz Generation
**Purpose**: Produce a short, varied quiz (multiple‑choice) based on lesson material.
**Runtime Variables**:
- `{{lesson_content}}`
- `{{lesson_metadata}}`
- `{{num_questions}}` (default 5)
**Prompt Template**:
```
Create {{num_questions}} multiple‑choice questions from the lesson below. For each question provide:
1. The question text.
2. Four answer options labelled A‑D.
3. The correct answer letter.
4. A brief explanation (≤ 30 words).

Lesson:
{{lesson_content}}
```
**Expected Output**: Markdown list of questions with sub‑items (A‑D, Answer, Explanation).
**Validation Rules**:
1. Exactly `{{num_questions}}` questions.
2. Four distinct options per question.
3. One correct answer indicated.
4. Explanations ≤ 30 words.
**Failure Conditions**:
- Missing options or answer → request completion.
- Exceeds explanation length → ask to shorten.
- Duplicate questions → regenerate.

## 3. Runtime Context Injection
When a prompt template is selected, the system injects the following pieces in the exact order listed below before sending to the LLM:
1. **User Query** – raw learner input.
2. **Retrieved Context** – the most relevant lesson excerpt(s) based on the selection rules (Section 5).
3. **Conversation History** – the last five turns of dialogue.
4. **Lesson Metadata** – ID, title, difficulty, tags, and completion status.

---

## 4. Context Selection Rules
- **Single Context** – Use the highest‑confidence snippet when only one matches.
- **Multiple Context** – Include up to two top‑scoring snippets, separated by a line break.
- **Empty Context** – Leave the *Retrieved Context* section blank; the template’s fallback logic will handle it.
- **Low Confidence Context** – If confidence < 0.45, treat as empty.
- **Conflicting Context** – Discard both snippets and trigger the *Missing Context* fallback.

## 7. Prompt Execution Flow
1. **User Query** – raw input from learner.
2. **Safety Pre‑Check** – profanity, hate‑speech, jailbreak, injection detection.
3. **Prompt Registry Lookup** – fetch the template metadata from the Centralized Prompt Registry (Day 2).
4. **Prompt Template Selection** – choose the appropriate template based on intent detection and context availability.
5. **Context Retrieval** – pull lesson excerpts according to Context Selection Rules.
6. **Runtime Context Injection** – assemble User Query, Retrieved Context, Conversation History, Lesson Metadata.
7. **Prompt Assembly** – combine the selected template with injected variables.
8. **LLM Response Generation** – send the assembled prompt to the language model.
9. **Response Validation** – apply the template’s Validation Rules.
10. **Fallback Evaluation** – if validation fails, trigger the corresponding fallback response.
11. **Final Response** – deliver the validated (or fallback) answer to the learner and log the interaction.

---

## 9. Prompt Selection Strategy
The system decides which template to use through a layered decision process.

1. **Intent Detection** – an NLU model extracts the primary intent (e.g., *ask‑question*, *summarize*, *generate‑quiz*). 
2. **Query Classification** – the intent is mapped to one of the seven template categories.
3. **Context Availability** – if the required context is missing, the *Missing Context* fallback is selected.
4. **Conversation State** – recent history may elevate *Follow‑up* or *Clarification* intents.
5. **Prompt Priority** – each template has a priority score; higher‑priority prompts are chosen when multiple intents overlap.
6. **Fallback Decision** – if safety checks fail or no template matches, the appropriate fallback category (Section 6) is applied.

This flow runs before the execution steps outlined in Section 10.

## 10. Prompt Quality Checklist
Every prompt template must satisfy the following checklist before being promoted to the registry:

- [ ] **Context Awareness** – uses `{{lesson_content}}` or equivalent.
- [ ] **Runtime Variable Coverage** – all required variables are listed in the template.
- [ ] **Validation Rules** – explicit rules for length, format, citations, etc.
- [ ] **Failure Conditions** – clear remediation paths.
- [ ] **Security Compliance** – respects safety pre‑check.
- [ ] **Reusability** – generic enough for multiple lessons.
- [ ] **Consistent Formatting** – markdown tables, code fences, bullet style.
- [ ] **Enterprise Documentation Standards** – aligns with Day 1/Day 2 style.
